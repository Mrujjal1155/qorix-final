- Website Deposit (Mobile View) uses the connected bot wallet; its Connect action uses the shared Telegram login panel to sign into the existing linked account, not reassign it. Website deposits call `webStartDeposit`/`webSubmitDepositTxid` in the bot engine so verification and settlement stay single-path.
- Mobile View customer login is Guest (no session) or Connect Telegram: `web_login_codes` (browser keeps secret, bot confirms `/start wlg_<code>`) signs into the website account tied to `profiles.telegram_id`; wallet/orders are read from the bot user, never copied.
- Reseller portal (/reseller) and docs follow Mobile View; its Reseller Dashboard button leads to /reseller/start and /reseller/panel, which (with /reset-password) always use the classic design via useMobileTemplate.
- Product Premium artwork uses current website-only saved media prepared by trusted admin saves and bounded scheduled reconciliation; explicit pending/reset values override old captured maps, so new/changed products need no source-code capture. Category captures remain independent; animation players load only after hydration to keep SSR browser-safe.
- Direct store product/catalogue URLs select native bot messages and keyboards, not Basic content wrapped in BotPage; share the quantity picker to preserve checkout behavior. AccountShell honors Mobile View so fallback customer pages never show Basic sidebars; catalogue loader data seeds the first client render to avoid hydration mismatch.
- Mobile menu "Reseller API" opens the in-page BotApiPanel (bot-identical card, table and actions via web-api-panel.functions); only API Docs links out, and Reseller Dashboard keeps the /reseller login/docs route.
- The API panel renders the bot's exact Premium emoji artwork (resolved by `resolveApiPanelIcons`, cached in `api_icon_media_*`, public Supabase artwork only), so this section keeps emoji artwork while the rest of Mobile View stays on icons.
